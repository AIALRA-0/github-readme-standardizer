# 中文写作规则衔接

## 1 保持一个规则来源

每次编写中文首页前读取当前安装的 `human-readable-technical-writing` 入口，再按照该入口的任务路由读取当前 README 命中的参考文件

不要把本仓库历史上的术语简写、固定叙事顺序或检查程序的有限匹配范围当作替代依据

本仓库不修改该写作技能，不要求用户安装历史评测工具，不引入其他助手投票

本技能独立负责首标题区域与头图的结构约束，并把当前中文写作技能规定的全部图片、表格、流程图及题注共同居中要求落实到 GitHub README 模板、审计器和渲染验证

## 2 在页面中落实

- 首屏用日常语言说明对象和结果，产品名称保持原名，需要专业知识的说明放在首次使用位置
- 专业术语首次使用一个完整列表项，以规定的中英文形式开头，用三至五句连续说明本质、目的、原理、适用条件和区分边界
- 同一定义保持连续，内部概念按规则配齐中英文但不递归展开百科
- 后文优先用已经解释的中文名，保留英文或缩写时仍需配对，反引号不能豁免普通名称
- 中文顺序操作使用项目符号和“第一步、第二步”等步骤词，说明执行位置、前提、输入、正常结果及当前步骤相关的异常处理
- 新写命令按功能块添加合法头行注释，逐行讲解时使用对齐的同行注释
- 不可合法注释的配置保留原字符，在对象外逐行解释
- 图片和流程图先显示，再在下方说明阅读起点、可见元素、相互关系和图中不能确认的内容；对象与图题放在同一个居中容器
- 表格适合精确比较，原始表格不改数据，表题放在表格上方，并与表格放在同一个居中容器；表格下方解释列与行的对应方式和结论限制
- 根首页需要的定义留在使用位置，长参数表和完整教程进入详细文档，不能为缩短篇幅删掉上手前提

## 3 复核和局部修复

重新打开写作技能入口和本次命中的参考文件，逐块对照当前成稿，不能凭记忆声明通过

有本地工具时按该技能的 `references/local-review.md` 保存任务临时初稿，执行 `scripts/review_writing.py`，由同一助手判断语义疑点

确认问题后通过该技能的局部提交器修复，最多两轮，不整篇重写已完成的成稿

本仓库的 `scripts/audit_readme.py` 只补充文件、链接、双语结构和已知模式检查，无法证明术语五段逻辑、事实完整性或读者理解

机械检查与内容复核分别记录，不用测试数量、篇幅或全部通过字样代替用户实际阅读反馈
