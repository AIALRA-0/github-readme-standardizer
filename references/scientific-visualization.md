# 科学制图协议

## 1 适用范围

实验结果、性能基准、模型评测、误差分析、资源消耗和时间序列进入 README 时使用本协议

没有可公开数据、复现方法或统计定义时，只说明验证方法和证据缺口，不绘制推测性曲线

## 2 图形选择

<div align="center">

表 2.1　数据任务与图形类型

| 读者问题 | 推荐图形 | 避免 |
|---|---|---|
| 多组数值怎样比较 | 点图、区间图或从零开始的柱状图 | 用面积或立体效果夸大差异 |
| 指标随时间怎样变化 | 折线图与置信带 | 不规则采样却暗示连续变化 |
| 分布和异常值怎样 | 箱线图、小提琴图或直方图 | 只给平均值 |
| 两个变量是否相关 | 散点图、拟合线和不确定性 | 把相关写成因果 |
| 多指标取舍怎样 | 小多图或标准化矩阵 | 无共同尺度的雷达图 |

</div>

## 3 必备语义

每张科学图需要提供图题、横纵轴名称、单位、样本量、聚合方法、误差或置信区间定义、数据来源、测试环境、更新时间和复现入口

截断坐标轴、对数尺度、归一化、平滑、插值、缺失值处理和异常值排除必须在图题或紧邻正文中说明

颜色不能是唯一编码。线型、点型、标签或直接标注需要帮助色觉差异读者辨别系列

## 4 视觉规则

- 一张图只回答一个主要问题，复杂结果拆成带字母编号的小多图
- 文字在 GitHub 内容宽度和窄屏缩放后仍可读
- 网格线弱于数据，图例靠近数据，数值精度不超过测量能力
- 比较基线使用稳定中性色，项目结果使用一个主要强调色，风险或失败使用语义色
- 默认提供表格或机器可读数据入口，图片不能成为唯一数据载体

## 5 可复现交付

图形应由版本控制中的脚本和公开或合成数据生成。记录随机种子、依赖版本、输入摘要和输出路径

生成结果进入 `docs/assets/readme/plots/`，脚本进入仓库现有分析目录或 `scripts/`。README 中的数字需要与图形源数据和验证记录一致

## 6 验收

由维护者、领域读者和非专业读者分别回答：图展示了什么、条件是什么、能否复现、不能推出什么结论。任一答案依赖猜测时，补齐标注或删除结论
