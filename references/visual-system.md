# README 视觉系统

## 1 视觉目标

视觉资源需要提高识别、理解或验证效率

装饰元素占用首屏但无法支持读者任务时删除

## 2 视觉层级

- 品牌标识和一级标题建立项目身份
- 价值短句说明目标用户和主要结果
- 可信徽章展示版本、检查、语言、安全或许可证状态
- 主视觉证明界面、终端行为、架构、模型能力或内容结构
- 三列以内的能力卡支持快速扫描
- 表格表达精确比较，Mermaid 文本绘图表达流程、架构和责任关系
- 项目动态、星标趋势和社区热度位于页面末尾，只承担补充说明

详细组合顺序见 [模块目录](module-catalog.md)

## 3 资源规则

- 优先使用仓库内资源，避免 README 依赖远程图片服务
- 亮色和暗色需要不同资源时使用 HTML `picture` 元素和主题媒体条件
- 截图需要裁去浏览器栏、账户菜单、通知、用户标识、内部路径、真实网址和图片元数据
- 图片替代文本说明图片展示的对象和读者能够得到的结论
- 关键步骤同时保留正文，图片失效后读者仍能完成主要任务
- 动态图片只用于展示静态截图无法表达的核心交互，并提供静态后备图
- 表格在窄屏允许局部横向滚动，整页保持无横向溢出

生成图片与本地资产见 [图片生成与视觉生产](visual-production.md)

产品截图、用户流程和渲染稳定性见 [UI、UX 与页面稳定性](ui-ux-evidence.md)

## 4 徽章规则

默认保留能够改变采用判断的状态，例如版本、构建、语言、安全和许可证

静态徽章需要由项目事实生成

动态徽章需要分别核对服务权限、请求日志、缓存策略和失效行为

星标、访问量、活动图和社交热度默认省略；确实改变采用判断时按照 [徽章、统计与项目动态](metrics-and-badges.md) 放在页面末尾

## 5 图表规则

流程关系优先使用 `flowchart TD`，节点从上到下排列

架构图需要说明组件、数据方向、信任边界和外部依赖

性能图需要在图旁列出条件、样本、单位、复现入口和更新时间，并遵守 [科学制图协议](scientific-visualization.md)

图题放在图形下方，表题放在表格上方，补充说明使用“注：”

## 6 视觉验收

分别检查亮色、暗色和窄屏环境中的文字对比度、图片完整性、表格可读性、代码滚动和页面级横向溢出

最终审核需要查看渲染像素，源文件检查不能替代视觉检查

所有视觉还需要按照 [视觉隐私与脱敏协议](visual-privacy.md) 检查像素、源码、元数据和外部请求
