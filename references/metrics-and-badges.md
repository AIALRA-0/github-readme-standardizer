# 徽章、统计与项目动态

## 1. 指标分层

可信状态位于首屏，社区热度位于页面末尾

首屏可以展示当前构建、发布版本、许可证、支持平台、安全策略和文档语言；星标、访问量、下载量、贡献热力、活动图和趋势曲线属于补充信息

## 2. 数据来源

- 首选 GitHub 原生状态、仓库发布记录和项目持续集成结果
- 静态徽章由可核对事实生成并保存在仓库内
- 动态徽章需要确认提供方会收到哪些请求数据、是否记录来源页面、缓存多久、失效时展示什么
- 星标趋势等第三方图表需要标注提供方和查询范围，不能宣称实时或完整，除非接口与刷新机制能够证明

## 3. 选择门禁

一个指标只有同时满足以下条件才进入 README：它会影响当前读者的判断；定义和来源明确；不会泄露私有仓库或访问者信息；失效不会破坏核心路径；有人负责维护

同一事实不同时使用文字、多个徽章和图表重复展示；徽章数量以首屏仍能快速识别项目为上限

## 4. 项目动态模块

项目动态放在限制和维护入口之后，推荐顺序为当前发布、构建状态、开发活动、社区趋势

没有稳定数据时使用本地状态表，不放空图、假趋势或模拟星标；私有仓库默认不接入需要把仓库标识发送给第三方的统计服务

## 5. 降级与存档

远程统计服务不可用时，README 需要保留文字入口和本地事实；需要长期保存的统计快照应记录采集日期、查询条件和来源，不把快照描述成当前值

动态指标发生含义变化、接口迁移或连续失效时，先移除展示，再决定是否替换服务
