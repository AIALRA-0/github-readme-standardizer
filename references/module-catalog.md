# README 可复用模块目录

## 1 组合原则

每个 README 先启用七个核心模块，再按照仓库证据选择条件模块

核心模块包括项目身份、价值范围、第一视觉证据、首次成功、验证限制、安全入口和维护入口

条件模块不能挤占核心任务的位置，也不能因为视觉效果丰富就保留无证据内容

## 2 推荐顺序

表 2.1　模块位置与启用依据

| 页面位置 | 模块 | 启用条件 | 主要证据 |
|---|---|---|---|
| 首屏 | 品牌、标题、价值短句、状态、稳定入口 | 所有项目 | 仓库名称、当前状态、真实文档入口 |
| 首屏之后 | 主视觉 | 能证明主要交付物 | 脱敏界面、终端结果、架构关系或内容地图 |
| 正文前部 | 价值、能力、首次成功 | 所有项目 | 代码、配置、测试和可复现命令 |
| 正文中部 | 界面组图或科学图 | 界面、研究数据或基准是采用依据 | 可复核像素、数据、脚本和图题 |
| 正文中部 | 架构、信任边界或用户流程 | 组件关系会影响使用或风险判断 | 数据方向、外部依赖、人工确认点 |
| 正文后部 | 验证、兼容、安全、限制 | 所有项目 | 当前检查、平台范围和失败边界 |
| 页面末尾 | 项目动态与社区指标 | 指标来源、隐私和失效行为已批准 | 发布、构建、星标或贡献趋势 |

</div>

项目动态不能成为第一证据。星标和访问量只能说明关注度，不能代替功能、质量、性能或安全证据

## 3 条件模块选择

- 有真实产品界面时，启用界面组图和界面稳定性矩阵
- 有实验、基准或统计结论时，启用科学制图模块
- 需要解释数据流、信任边界或责任关系时，启用 Mermaid 或本地矢量图
- 需要品牌插画、场景图或无法直接截图的概念图时，启用图片生成模块，并明确它是说明图而不是运行证据
- 动态徽章、星标、下载量、贡献热力或趋势图只在页面末尾启用
- 任何视觉包含账户、真实数据、地址、路径或外部资源时，先启用视觉隐私门禁

## 4 可复制资源

- 中文条件模块位于 [`assets/visual-modules.zh.md`](../assets/visual-modules.zh.md)
- 英文条件模块位于 [`assets/visual-modules.en.md`](../assets/visual-modules.en.md)
- 两份文件按同一编号组织，启用一个模块时同步复制、填写和验证
- 模板中的占位值只表示信息位置，交付前必须替换或删除整个未启用模块

## 5 删除规则

出现以下情况时删除条件模块：数据来源不明、截图无法脱敏、数字无法复现、外部图片服务无法解释、英文版本无法同步，或模块没有改变读者的理解与下一步
