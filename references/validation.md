# README 验证协议

## 1 确定性检查

在技能目录运行以下命令：

```powershell
python scripts/audit_readme.py "<repository-path>" --strict-warnings # 使用仓库路径占位值审核双语 README、链接、资源、编号、Mermaid 和已知敏感模式
```

脚本输出 JSON 结构化结果，`errors` 中的每个问题都属于交付阻断项，`warnings` 需要人工确认；正式发布使用 `--strict-warnings`，未确认提醒同样阻止自动合并

确定性检查覆盖中英双语结构、本地链接、替代文本、十进制编号、装饰性编号、Mermaid 竖向方向、已知秘密形状、私有网络地址、用户目录路径、SVG XML 结构、活动内容、事件处理器、外部引用、稳定尺寸和常见位图元数据容器

默认扫描范围包括中英文 README 及其引用的本地文档和视觉资产

需要扩大到整个仓库时使用以下命令：

```powershell
python scripts/audit_readme.py "<repository-path>" --scan-repository # 使用仓库路径占位值扩展扫描源码、测试夹具和未被 README 引用的文件
```

仓库确实需要保留上游文档示例时，可以在根目录添加 `.readme-audit-allowlist.json`

例外只支持 `PRIVATE_IPV4` 检查，并同时锁定仓库相对路径、匹配文本的 SHA-256 摘要和预期出现次数

例外文件不得保存原始匹配文本，每一项需要写明不少于 20 个字符的审核理由

扫描结果会把已应用例外列为提醒，匹配内容、路径或次数发生变化时会成为交付阻断项

## 2 仓库验证

- 第一项，运行仓库已有的格式、测试、构建或文档检查，记录命令和结果
- 第二项，检查 README 中的安装和最小示例，确认命令与当前版本一致
- 第三项，检查相对文件、图片、页内入口和外部证据链接
- 第四项，核对中英文版本、命令、图片、图表编号、状态和限制
- 第五项，扫描文本秘密、图片像素和图片元数据
- 第六项，科学图核对轴、单位、样本量、不确定性、数据来源、处理方法和复现入口
- 第七项，动态徽章与趋势图核对提供方、请求数据、缓存、失效行为和页面末尾位置

## 3 GitHub 渲染

使用 GitHub Markdown 应用程序接口或仓库预览确认 HTML、表格、图片、详情块和 Mermaid 标记得到保留

本地预览需要模拟 GitHub 内容宽度，并分别采用亮色、暗色和窄屏视口

渲染结果需要满足以下条件：

- 所有图片完整加载
- 页面没有整体横向溢出
- 亮色、暗色和窄屏中的标题、标签、轴、图例和界面状态均可读
- 标题和页内入口能够到达正确章节
- 图片替代文本、表题、图题和警告在图片失效时仍可理解
- 代码和表格只在自身区域内滚动
- 项目动态位于核心内容之后，远程统计失效不影响首次成功路径

## 4 人工审核

自动检查无法判断截图是否泄露用户信息、营销声明是否合理、第一证据是否有说服力、科学结论是否成立或章节是否符合真实读者任务

人工审核需要完成首次访问者、维护者和安全审核者三个视角

连续两次试点没有减少无关章节或没有改善首次成功路径时，合并或收紧项目路由

任一正式版本出现双语、徽章、截图或命令漂移时，重新审核模板和同步门禁

## 5 交付记录

交付内容列出修改文件、视觉预览、自动检查、仓库检查、已知限制、未执行事项和远程仓库状态
