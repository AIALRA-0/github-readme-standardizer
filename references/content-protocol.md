# README 内容协议

## 1 核心组件

所有项目需要回答同一组读者问题，视觉大小和正文长度按照项目事实调整

<div align="center">

表 1.1 README 核心组件

| 顺序 | 组件 | 需要回答的问题 | 最小证据 |
|---:|---|---|---|
| 1 | 项目身份 | 项目叫什么，当前状态是什么，语言怎样切换 | 项目名、价值短句、状态、语言入口 |
| 2 | 价值范围 | 为谁解决什么问题，排除哪些用途 | 目标读者、主要结果、适用边界 |
| 3 | 第一证据 | 项目形态或运行关系是什么样 | 截图、终端输出、架构图、能力表或内容地图 |
| 4 | 首次成功 | 读者怎样得到可观察结果 | 前置条件、操作、输入、输出和失败边界 |
| 5 | 验证限制 | 哪些内容已经验证，证据覆盖到哪里 | 测试命令、版本范围、数据来源和限制 |
| 6 | 安全入口 | 密钥、身份信息和安全报告怎样处理 | 占位值、数据边界和私密报告入口 |
| 7 | 维护入口 | 怎样获得帮助、贡献和确认授权 | 支持渠道、贡献指南和许可证 |

</div>

## 2 首屏协议

推荐首屏顺序：品牌标识 → 一级标题 → 一句话价值 → 可信徽章 → 少量稳定入口 → 语言切换 → 第一视觉证据

所有 README 的一级大标题统一使用语义化 `<h1>`，并通过 `align="center"` 或带 `align="center"` 的外层容器居中；Markdown `# 标题`、CSS 样式模拟居中和未居中的 `<h1>` 不符合发布规范

标志不能代替一级标题，徽章不能代替项目状态说明，截图不能代替快速开始

第一视觉证据应该证明项目的主要形态，装饰图片和星标历史不承担核心证据职责

完整模块位置、启用依据和删除规则见 [模块目录](module-catalog.md)

## 3 快速开始

快速开始需要包含前置条件、最小安装或启动动作、预期结果和下一条安全路径

远程脚本直接进入命令解释器时，同时提供校验方式和包管理器或手动安装路径

命令和配置示例使用占位组织名、无效示例域名、合成用户标识和最小权限

## 4 条件模块

<div align="center">

表 4.1 README 条件模块

| 模块 | 启用条件 | 证据不足时的处理 |
|---|---|---|
| 性能基准 | 条件、数据、脚本和更新时间均可公开 | 删除倍数和排名，链接验证方法 |
| 用户评价 | 引文、身份、授权和原始来源均可核对 | 删除评价 |
| 采用者或赞助商 | 已取得展示授权并指定维护人 | 移入独立页面 |
| 下载量或星标 | 指标会改变当前读者的采用判断 | 默认省略 |
| 在线演示 | 使用隔离合成数据并经过安全审核 | 提供本地演示 |
| 动态徽章 | 外部服务经过隐私与稳定性批准 | 使用本地静态徽章或文字状态 |
| 自托管风险门 | 项目接触文件、数据库、网络或凭据 | 先提供隔离验证路径 |
| 多仓库职责 | 组件、维护主体和问题渠道能够核对 | 只列当前仓库职责 |
| 许可证解释卡 | 许可证名称无法说明自托管或商业边界 | 链接许可证原文 |
| 生成式主视觉 | 需要解释性或品牌视觉，且不会伪装成运行证据 | 使用真实架构、终端或能力表 |
| 科学图 | 数据、统计定义和复现入口均可公开 | 只列验证方法和证据缺口 |
| 界面组图 | 合成环境能够覆盖完整用户任务 | 使用脱敏流程图或文字步骤 |
| 项目动态 | 指标影响采用判断，来源与隐私已经批准 | 删除或使用仓库原生文字入口 |

</div>

## 5 双语协议

默认文件为中文 `README.md` 和英文 `README.en.md`

两份文件需要同步以下共享事实：版本、命令、平台、图片、图表编号、运行状态、限制、安全入口、贡献入口和许可证

翻译保持读者任务和证据边界一致，无需逐句机械对应

项目名称、命令、文件名、接口名和官方产品名保持原始拼写

## 6 根文件边界

根 README 负责价值判断、首次成功、安全边界和维护入口

完整接口、全部参数、部署变体、长篇排障、维护手册和研究附录进入 `docs/`

根文件中的每个外链需要回答当前读者为什么要离开首页

项目动态、星标趋势和社区指标位于限制与维护入口之后，不得提前到首屏或首次成功路径
