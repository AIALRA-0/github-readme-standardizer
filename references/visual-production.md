# 图片生成与视觉生产

## 1. 先确定证据角色

生成图片前先写一句用途声明：这张图帮助哪类读者判断什么

视觉分为三类：

- 真实运行证据
- 解释性图形
- 品牌装饰

生成式图片只能默认承担解释或品牌角色，不能伪装成产品截图、实验结果、用户评价或真实部署画面

## 2. 输入规格

每次生成或绘制需要固定以下内容：

- 画布比例、目标显示宽度和亮色或暗色背景
- 项目名称、主要对象、读者需要看懂的关系和禁止出现的元素
- 品牌颜色、文字层级、留白、边缘安全区和移动端裁切范围
- 是否允许文字；允许时只保留短标题，长说明进入 Markdown 正文
- 文件格式、透明背景要求、替代文本和事实性图题

提示词中禁止加入真实姓名、账户、地址、路径、密钥、客户数据、内部产品代号或未公开界面

## 3. 生产路径

- 标志、架构、流程、徽章和简单几何图优先使用仓库内 SVG，便于主题适配和源码检查
- 照片感、插画、复杂纹理和场景概念图可以使用图片生成工具，输出后保存为本地 PNG 或 WebP
- 产品截图来自合成演示环境，不使用生成图替代真实功能证据
- 图内文字较多时使用 HTML、Markdown、Mermaid 或程序化制图，避免生成模型产生错误字符
- 同一主视觉至少检查桌面宽度和窄屏裁切；重要信息不能只位于边缘

## 4. 文件与版本

视觉文件进入 `docs/assets/readme/`，使用角色和主题命名，例如：

- `hero-light.svg`
- `workflow-dark.svg`
- `ui-dashboard.webp`

保留可复现源文件或生成说明，包括：

- 工具
- 输入规格
- 人工修改
- 生成日期

README 只链接最终优化文件，不嵌入临时导出、编辑器缓存或原始提示中的敏感内容

## 5. 验收

- 图形与仓库事实一致，没有虚构按钮、数字或状态
- 替代文本说明对象和结论，不重复“图片”两个字
- 亮色、暗色和窄屏均可读，图片失效后正文仍能完成主要任务
- 本地文件扩展名与字节格式一致，矢量图没有脚本、事件处理器、外部引用或未审查元数据
- 发布前按照视觉隐私协议检查像素、源码和元数据
