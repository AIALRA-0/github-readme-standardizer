# 项目类型路由

## 1 选择规则

主路由由仓库的主要交付物和首次成功动作决定

混合仓库选择一个主路由，再叠加少量条件模块，同时拼接多个完整路由会造成章节重复和读者目标冲突

## 2 用户应用型项目

适用对象包括网页应用、桌面应用、移动应用和拥有完整用户界面的工具

推荐顺序：品牌首屏 → 真实截图 → 上手路径 → 核心能力 → 快速开始 → 用户流程 → 数据安全 → 质量状态 → 支持与许可

第一证据优先使用脱敏后的真实界面，截图缺失时使用能够反映用户流程的原型或流程图

## 3 开发接口型项目

适用对象包括开发库、软件开发工具包和应用程序接口组件

推荐顺序：项目身份 → 版本兼容 → 安装 → 最小代码 → 核心概念 → 接口范围 → 迁移限制 → 验证 → 安全与许可

第一次成功需要展示输入、调用和可观察输出，兼容声明需要关联当前版本证据

## 4 命令行工具型项目

适用对象包括终端工具、包管理器、构建工具和本地自动化程序

推荐顺序：项目身份 → 平台支持 → 终端证据 → 适用边界 → 安装矩阵 → 命令配置 → 比较验证 → 构建测试 → 安全与许可

终端演示需要使用合成目录和占位标识，性能比较需要公开复现方法

## 5 基础设施服务型项目

适用对象包括持续运行的服务、自托管平台、数据库组件和控制平面

推荐顺序：项目身份 → 问题与特性 → 架构 → 部署渠道 → 最小配置 → 健康检查 → 集成插件 → 升级备份 → 网络安全 → 贡献与许可

部署路径会改变数据、网络和凭据风险，因此环境要求和风险门需要靠近安装入口

## 6 人工智能数据型项目

适用对象包括模型、数据集、训练框架、评测项目和研究代码

推荐顺序：项目身份 → 模型与数据许可 → 预期用途 → 安装 → 最小运行 → 任务范围 → 评测复现 → 限制与安全 → 隐私与成本 → 引用与贡献

研究状态、模型能力和评测数字需要区分已发布、准备发布和规划内容

## 7 技术内容型项目

适用对象包括书籍、课程、知识库、规范和文档源码

推荐顺序：项目身份 → 内容范围 → 发布版本 → 阅读入口 → 构建预览 → 内容地图 → 贡献规范 → 翻译流程 → 质量验证 → 许可与致谢

内容版本、产品版本和翻译状态需要分别写明所属对象

## 8 跨类型条件

- 自托管项目增加部署选择、环境要求、备份恢复和权限边界
- 多仓库项目增加组件架构、仓库职责、维护主体和问题路由
- 高风险项目增加数据损失、代码执行、外部写入和恢复路径
- 多平台项目增加平台能力矩阵和平台专用安装说明
- 多语言项目增加维护责任、同步检查和主语言入口
