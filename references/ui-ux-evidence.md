# UI、UX 与页面稳定性

## 1. 界面证据

界面截图需要覆盖一个完整用户任务，而不是展示最多页面

推荐组合为：一个主界面、一条关键流程和一个结果或错误状态；每张图在图题中说明触发条件、可观察结果和是否使用合成数据

## 2. 截图规格

- 统一窗口尺寸、缩放比例、语言、主题和数据状态
- 裁去浏览器栏、系统托盘、账户菜单、通知和无关桌面区域
- 使用合成头像、组织、项目、文件、日期和业务数据
- 光标、悬浮提示和焦点状态只有在解释交互时保留
- 动画提供静态后备图，并避免快速闪烁和无限自动播放

## 3. README 界面层级

首屏只保留身份、价值、可信状态、稳定入口和第一视觉证据

能力卡最多三列，卡片文字保持短句；精确比较使用 Markdown 表格，流程使用 Mermaid，复杂产品状态使用本地截图组

项目动态、星标趋势、贡献热力和访问统计位于页面末尾，不能打断首次成功与安全说明

## 5. 尺寸与加载

为主要图片提供稳定宽度或可缩放的 `viewBox`；避免将大尺寸原图直接缩小显示；在不损害可读性的前提下压缩文件

同一图形需要主题版本时使用 `picture` 和 `prefers-color-scheme`，并保留默认 `img` 后备图

外部图片会泄露请求信息并产生失效风险，默认改为仓库内资源；确需远程资源时记录服务、请求数据、缓存、维护人和降级方式

## 6. 像素审核

源文件检查不能替代渲染检查；发布前查看 GitHub 实际像素，分别检查桌面亮色、桌面暗色和窄屏，并记录任何未执行场景
